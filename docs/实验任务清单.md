- 原因：ASSIST09数据集特性导致Phase 2 RL效果不佳

**实验配置** (表4.4):
```python
# ASSIST09
embed_dim: 128
hidden_dim: 256
n_layers: 2
alpha: 0.7
beta: 0.3
lambda_decay: 0.1
gamma: 0.99
lr_kt_pretrain: 0.001
lr_kt_finetune: 0.0005
lr_rl: 0.0001
batch_size: 64
dropout: 0.35        # 优化：增强正则化
l2_lambda: 5e-5      # 优化：L2正则化
max_seq_len: 150
n_epochs: 50         # KRD-KT-SL: 仅Phase 1
patience: 5
```

**运行命令**:
```bash
# ASSIST09 (5次运行) - 使用 --mode 参数指定模型变体

# python experiments/run_experiment.py --dataset assist09 --mode full --n_runs 5
```

## 💡 消融实验框架说明

### ✅ 已集成到 `run_experiment.py`

消融实验通过 `--mode` 参数控制，无需单独脚本。

### 支持的模式

| Mode | 说明 | 对应论文表4-3 |
|------|------|---------------|
| `full` / `default` | KRD-KT 完整版 | KRD-KT (基准) |
| `sl` | KRD-KT-SL | KRD-KT-SL |
| `wo_3wd` | w/o Three-way Decision | KRD-KT w/o 3WD |
| `wo_multi` | w/o Multi-order | KRD-KT w/o Multi-order |
| `wo_diff` | w/o Diff-Msg | KRD-KT w/o Diff-Msg |
| `wo_decay` | w/o Decay | KRD-KT w/o Decay |
| `wo_neg` | w/o Neg-Suppress | KRD-KT w/o Neg-Supp |

### 使用示例

```bash
# 运行完整版
python experiments/run_experiment.py --dataset assist09 --mode full --n_runs 5

# 运行KRD-KT-SL（当前ASSIST09使用）
python experiments/run_experiment.py --dataset assist09 --mode sl --n_runs 5

# 运行消融实验变体
python experiments/run_experiment.py --dataset assist09 --mode wo_3wd --n_runs 5
python experiments/run_experiment.py --dataset assist09 --mode wo_multi --n_runs 5
python experiments/run_experiment.py --dataset assist09 --mode wo_diff --n_runs 5
python experiments/run_experiment.py --dataset assist09 --mode wo_decay --n_runs 5
python experiments/run_experiment.py --dataset assist09 --mode wo_neg --n_runs 5
```

### 文件命名

根据 `mode` 自动生成对应的变体名称：

```
checkpoints/{dataset}/
  └── {model_variant}_run{N}_{dataset}.pt

results/
  ├── {model_variant}_run{N}_{dataset}.json
  └── {model_variant}_{dataset}.json  # 汇总
```

例如 `--mode wo_3wd`:
- Checkpoint: `krd_kt_wo_3wd_run1_assist09.pt`
- Results: `krd_kt_wo_3wd_assist09.json`

### 详细文档

- **消融实验使用指南**: `docs/消融实验使用指南.md`
- **技术实现细节**: 见 `models/krd_kt.py`, `models/triple_decision_graph.py`

### 阶段3：基线模型对比实验 (4.4 + 4.5) ⏳

#### 任务3.1：实现基线模型
**状态**: ⏳ 待开始

需要实现以下基线模型：

1. **DKT** (Deep Knowledge Tracing)
   - 基于循环神经网络的经典知识追踪模型
   - 文件: `baselines/dkt.py` ✅ (已实现)

2. **DKVMN** (Dynamic Key-Value Memory Network)
   - 基于记忆网络的知识追踪方法
   - 文件: `baselines/dkvmn.py` ✅ (已实现)

3. **SAKT** (Self-Attentive Knowledge Tracing)
   - 基于 Self-Attention 的序列建模方法
   - 文件: `baselines/sakt.py` ✅ (已实现)

4. **AKT** (Attentive Knowledge Tracing)
   - 基于注意力机制的知识追踪模型
   - 文件: `baselines/akt.py` ✅ (已实现)

5. **GKT** (Graph-based Knowledge Tracing)
   - 基于图神经网络的知识追踪模型
   - 文件: `baselines/gkt.py` ✅ (已实现)

**说明**: 论文原定基线包括SAINT和DKTMR，但根据实际情况已替换为SAKT和AKT。

## 🎯 消融实验框架特性

### ✨ 主要特点

1. **统一接口**: 所有变体通过 `--mode` 参数控制
2. **自动命名**: 根据mode自动生成对应的文件名
3. **配置隔离**: 每个mode有独立的配置覆盖
4. **向后兼容**: 支持不带mode参数的旧命令（默认为sl）
5. **完整测试**: 所有7种模式配置已验证通过

### 🔧 技术亮点

- **模块化设计**: 消融配置与基础配置分离
- **灵活适配**: 模型架构根据配置自动调整
- **方案A实现**: 三支决策可退化为标准GNN（统一处理）
- **零代码重复**: 无需为每个变体编写单独的模型类

### 📊 实验效率

使用消融框架可以：
- ✅ 快速切换不同变体
- ✅ 统一的结果文件格式
- ✅ 便于对比分析
- ✅ 降低实现错误风险
