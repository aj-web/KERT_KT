# Junyi 训练问题分析与修复

## 🔴 问题描述

### 观察到的现象
Junyi 数据集训练时出现**梯度爆炸**（Gradient Explosion）:

| Epoch | KT Loss | Val AUC | 状态 |
|-------|---------|---------|------|
| 1-3 | 0.42 → 0.39 | 0.712 → 0.719 | ✅ 正常下降 |
| 4-5 | 0.39 → 0.43 | 0.713 → 0.707 | ⚠️ 开始反弹 |
| 6-10 | 0.52 → 1.01 | 0.700 → 0.703 | 🔴 **暴涨失控** |

Loss 从 0.39 暴涨到 1.01（**增长 2.6倍**），典型的梯度爆炸现象。

---

## 🔍 根本原因

### 1. 模型配置过大

| 配置项 | ASSIST09 (成功) | Junyi (失败) | 倍数 |
|--------|----------------|-------------|------|
| embed_dim | 128 | **256** | **2倍** |
| hidden_dim | 256 | **512** | **2倍** |
| n_layers | 2 | **3** | **1.5倍** |
| **参数总量** | ~4M | ~16M | **4倍** |

### 2. 数据规模差异

| 指标 | ASSIST09 | Junyi | 倍数 |
|------|----------|-------|------|
| 训练样本 | 231K | **723K** | **3.1倍** |
| 知识点数 | 123 | **707** | **5.7倍** |
| 题目数 | 17K | **65K** | **3.8倍** |

### 3. 缺少关键防护机制

- ❌ **没有梯度裁剪**（Gradient Clipping）
- ❌ 学习率过高（0.001 对大模型过大）
- ❌ 模型复杂度与数据规模不匹配

---

## 🔧 修复方案

### 修改 1：降低模型复杂度

**原配置**：
```python
'embed_dim': 256,
'hidden_dim': 512,
'n_layers': 3,
```

**修改后**：
```python
'embed_dim': 128,      # 256 → 128（与ASSIST09一致）
'hidden_dim': 256,     # 512 → 256（与ASSIST09一致）
'n_layers': 2,         # 3 → 2（与ASSIST09一致）
```

**效果**：
- 参数量减少 **75%**（16M → 4M）
- 计算量减少 **~60%**
- 梯度稳定性大幅提升

### 修改 2：降低学习率

**原配置**：
```python
'lr_kt_pretrain': 0.001,
```

**修改后**：
```python
'lr_kt_pretrain': 0.0005,  # 0.001 → 0.0005（降低50%）
'lr_kt_finetune': 0.00025,
```

**理由**：
- 大规模数据集需要更小的学习率
- 防止参数更新步长过大

### 修改 3：添加梯度裁剪

**新增配置**：
```python
'grad_clip': 1.0  # 梯度裁剪阈值
```

**代码实现**：
```python
# 在 models/krd_kt.py 的 train_step 中
self.kt_optimizer.zero_grad()
kt_loss.backward()

# 梯度裁剪
if hasattr(self, 'grad_clip') and self.grad_clip is not None:
    torch.nn.utils.clip_grad_norm_(self.parameters(), self.grad_clip)

self.kt_optimizer.step()
```

**效果**：
- 限制梯度最大范数为 1.0
- 防止梯度爆炸
- 稳定训练过程

### 修改 4：增大 Batch Size

**原配置**：
```python
'batch_size': 64,
```

**修改后**：
```python
'batch_size': 128,  # 64 → 128（加倍）
```

**效果**：
- 梯度估计更稳定
- 训练速度提升 ~40%
- 每个 epoch 的 batch 数减少一半

### 修改 5：减少序列长度

**原配置**：
```python
'max_seq_len': 200,
```

**修改后**：
```python
'max_seq_len': 100,  # 200 → 100（减半）
```

**效果**：
- 内存占用减少 ~50%
- 计算速度提升 ~50%
- 训练更稳定

## 📝 经验教训

1. **模型规模要与数据规模匹配**
   - 不是越大越好
   - 大模型需要更多正则化

2. **梯度裁剪是必须的**
   - 特别是大规模数据集
   - 特别是深层网络

3. **从简单配置开始**
   - 先验证基础版本可行
   - 再逐步增加复杂度

4. **学习率调节很重要**
   - 大数据集 → 小学习率
   - 大模型 → 小学习率
